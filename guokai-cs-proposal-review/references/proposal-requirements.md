# 开题阶段学校要求与评审口径

依据文件（均在 `2026年秋季学期综合实践环节指导教师培训材料包\`）：

- 《计算机科学与技术专业毕业设计（论文）要求（2018 春修订）》
- 《国家开放大学实验学院实践教学环节管理规范（试行）》（国开校实验〔2018〕54 号）
- 《新的学位论文评价（评审）指标》（100 分四维；政法类专属条款不适用计科）
- 《论文规范性问题统计表》（35 篇退回：结构 32、语言 13、摘要 12、文献 12、**题目 11**、格式 9——题目问题应在开题阶段解决）
- 学校开题报告表单（五栏，见下）

## 一、开题报告表单（五栏，实测自学生提交件）

| 栏 | 栏名（表单原文措辞） | 学生应填内容 |
| --- | --- | --- |
| 封面 | 姓名／学号／教育层次／年级专业／题目 | 与学籍一致；题目与正文内容一致 |
| 第1栏 | 1.本选题的目的或意义，该选题目前研究现状、水平和发展趋势 | 意义＋**国内外研究现状综述**（现有做法→不足→本题切入点）＋发展趋势；行业断言须有文献支撑 |
| 第2栏 | 2.本选题的基本观点、研究主要方法、具体写作步骤 | 基本观点（核心方案）、研究方法（文献研究/需求分析/系统测试等）、**分步进度安排（含日期）** |
| 第3栏 | 3.论文提纲（二级提纲） | 论文 6—8 章骨架＋二级小节；两种体例均见：「第X章＋X.Y」与「一、＋（一）」 |
| 第4栏 | 4.与本选题相关的主要参考文献（…**参考文献应在5篇及以上**） | ≥5 条；论文阶段 ≥10 建议 15，开题即应按此准备 |
| 第5栏 | 5.指导教师意见：（对本课题的深度、广度及工作量的意见） | **由教师填写并签名日期，学生不得预填**；预填文字须清空 |

开题报告**没有**字数底线、摘要、关键词、目录、声明页栏位；论文的 6000 字底线、查重 <30%、图表题注与表格样式要求均属正文阶段，不得套用到开题。表单自身的字号差异（封面 14pt/正文 12pt）与栏名加粗属学校模板固有样式，确认学生未自行改动即可，不列问题。

## 二、时间节点（2026 秋；换学期须更新本表与脚本常量）

毕业设计 10 周、10 学分。每阶段至少 1 次指导，平台留痕。

| 阶段 | 截止 |
| --- | --- |
| 选题与开题 | 2026-11-15 |
| 初稿 | 2026-11-30 |
| 修改稿 | 2026-12-15 |
| 定稿 | 2026-12-27 |
| 答辩 | 2027-01-04 前 |
| 验收 | 2027-01-16 前 |

进度审核口径：按学校节点**倒排**；学生自排进度晚于任一节点即须重排（整体错位属严重问题）；查重是初稿/修改稿之后的子活动，不算节点交付；开发未完成时初稿可先写前 4 章，第 5—6 章系统完成后补，节点不变；必须留出测试与查重时间，不得砍测试章。

## 三、选题标准（K1 依据）

- 类型：软件系统开发类占约 95%，同质化严重；另有网站、移动开发、网络安全、多媒体/课件、网络规划设计、硬件、算法类。
- **五类问题题目**：
  - 假：业务不存在或学生无法接触（"某航空公司售票系统""量子计算机在××领域中的应用研究"）；
  - 大：范围超出 10 周单人工作量（集团 OA、网上商城）；
  - 空：调库实现基础功能、无具体任务/数据/指标（"大数据技术在医疗中的应用"式科普文；"X 技术在 Y 中的应用研究"句式默认警惕）；
  - 偏：非本专业（教改、就业趋势分析）；
  - 旧：技术栈过时（C 语言五子棋、单机版图书管理、Vue2 等新项目选 EOL 技术）。
- 好题目特征：限定范围/环境（小区失物招领小程序）、规模小复杂度低设备依赖低（校园二手交易）、有技术记忆点（微服务+并发、低代码、状态机+防冲突）。
- **往年重复题目榜**：学生信息管理(3)、酒店管理(2)、企业人事管理(2)、基于 web 的停车场管理(2)、基于 Java 的网上书城(2)、图书管理(2)、微信小程序医助 DRGS 药评(2)。
- 原则上 **1 生 1 题**；大题目可合作但须标注个人工作。批次内撞题须换题或严格互斥划界（写进开题报告与平台指导记录）。
- 批次撞题检查：先读项目记忆中的本学期选题评审记录（如 `project-thesis-topic-review-batch`），比对业务领域、核心判定逻辑与技术栈；巡检/点检/巡更/工单类须与已有题错位核心逻辑；推荐/协同过滤类先问"行为数据从哪来、指标怎么算、跟谁对比"。
- 内容已按选题意见改造的，**题目必须同步改**，不得沿用通用原题。

## 四、观测点产出承诺（提纲阶段查"承诺"，初稿查实物）

| 环节 | 论文必备产出（开题提纲/第2栏应承诺） |
| --- | --- |
| 需求分析 | 功能结构图、2—4 个核心用例图、用例描述表、业务流程图、可测非功能指标 |
| 系统设计 | 分层架构图、功能模块图、E-R 图（含联系基数）、表结构（字段/类型/主外键）、活动图或顺序图 |
| 系统实现 | 开发与运行环境表、核心功能截图（图题＋正文解释）、10—30 行关键代码含中文注释、实现难点与解决 |
| 系统测试 | 测试环境与条件表、测试用例表（编号/模块/步骤/输入/预期/实际/结论）、异常与越权用例、结果统计与修复记录 |

算法类变体：需求、算法流程图、核心代码、结果分析/验证（重复实验取均值±方差、基线对比）、输入接口设计。硬件类：原理图、PCB/接线、调试记录。
提纲阶段缺失承诺不判不合格，但须列问题要求补明；核心创新须有显性小节，不得淹没在"关键流程设计""核心模块实现"等通用节名中。

## 五、参考文献（开题口径）

- 表单底线 ≥5 条；建议开题即按论文标准准备 ≥10 条（论文建议 15 左右）。
- 近 5 年文献占一半以上；外文 2—3 篇（专业要求，开题可暂缺，**初稿前必须补齐**）。
- 类型以期刊[J]、学位论文[D]、专著[M]、标准[S]、官方技术文档[EB/OL]为主；百科、博客、论坛帖不宜作学术论据。
- GB/T 7714—2015 著录：编号[n]、作者、题名、类型标识、刊名/出版单位、年卷期页。知网/万方题录直接导出（"作者，题名 机构名 日期"式）缺类型标识与刊名卷期页，属不规范，须逐条重录；机构名≠出版单位。
- 正文引用：开题可宽松（作者姓名叙述可接受），但**悬空引用必须处理**（正文提及的作者无对应条目→补全或删除）；列而未引的条目→找落点引用或替换。初稿起凡引用处必须上标[n]并与文后一一对应。
- 真实性抽查 2—3 条（知网/万方/官网/DOI）；查不到写"未能核实"，不写"虚构"；查实虚构联动硬门槛。

## 六、成绩与估分口径

- 申请学位：指导教师初评≥80 → 答辩≥80 → 责任教师复审≥80；不申请学位按 60 分及格线。审核前必须确认口径。
- 100 分四维：选题与设计 20、结构与论证 40、时效与实践 20、规范与伦理 20。
- **开题阶段只有"选题与设计 20"可估分**（题目、范围、综述、方法、数据可靠性均已可判）；其余三维正文未写，一律"证据不足，暂不估分"，可注明已可判的部分（如文献年份达标）。
- 选题与设计锚点：18—20 聚焦具体场景、目标可验证、方法得当、进度合节点；15—17 基本可行但范围偏大或题目未体现核心；12—14 题目与内容脱节、承诺不成立；12 以下非本专业或假大空。
- 估分只用于定位问题，不替代指导教师评分与答辩小组评分。

## 七、硬门槛在开题阶段的适用

| # | 一票否决项 | 开题适用性 |
| --- | --- | --- |
| 1 | 非本专业选题 | 适用，成立即退回/换题 |
| 2 | 结构不完整 | 改判**表单五栏与提纲骨架完整性**；缺栏、缺总结章须补 |
| 3 | 逻辑断裂、前后矛盾 | 适用；开题限期改正，未达退回程度列严重问题 |
| 4 | 政治错误、价值观不正确 | 适用 |
| 5 | 学科知识运用错误 | 适用；**开题限期改正，初稿再犯触发否决**（概念误用如分级混入角色、命名错误如".NET Core 8"） |
| 6 | 文体不符 | 适用（开题报告文体，非工作总结/产品说明书） |
| 7 | 正文不足 6000 字 | **不适用**（开题无字数底线） |
| 8 | 查重超 30% 或 AI/降重痕迹 | 查重**不适用**；AI 痕迹仍按 A1—A8 取证，定性须实锤 |
| 9 | 虚假引用、AI 虚构文献 | 适用；悬空引用/未能核实先列待核，查实虚构才触发 |

## 八、证据口径

- 全文汉字数、文献条数、外文篇数、年份为脚本近似值，边界须人工复核；表单内文献以人工逐条清点为准。
- 进度日期无年份时由上下文推断（9—12 月属当年，1—8 月属次年），须人工复核。
- 技术承诺可行性、撞题、需求来源、前后一致性无法机检，必须人工审读。
- 文献查不到写"未能核实"；不虚构页码、分数、查重率。
- 开题报告属学生个人材料，只在本地处理，不上传外部服务。
